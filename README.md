## 🚀 Швидкий старт (локальне розгортання)

Виконайте наступні команди у терміналі для розгортання проєкту на вашому комп'ютері:

```bash
# 1. Клонуйте ВАШ створений репозиторій
git clone https://github.com/YOUR_USERNAME/your-coursework-repo.git
cd your-coursework-repo

# 2. Встановіть PHP та JS залежності
composer install
npm install && npm run build

# 3. Створіть файл конфігурації та згенеруйте ключ застосунку
cp .env.example .env
php artisan key:generate

# 4. Налаштуйте підключення до БД у файлі .env, після чого запустіть міграції та сідери
php artisan migrate --seed

# 5. Запустіть локальний сервер розробки
php artisan serve
```

Після запуску застосунок буде доступний за адресою: `http://127.0.0.1:8000`

## 🗂️ Рекомендована структура проєкту

Дотримуйтесь розподілу відповідальності (не пишіть бізнес-логіку та запити до зовнішніх API безпосередньо у контролерах):

```text
app/
├── Http/
│   ├── Controllers/      # Тонкі контролери (прийом запиту -> виклик сервісу -> повернення View/JSON)
│   └── Requests/         # FormRequest-класи для валідації вхідних даних
├── Models/               # Eloquent-моделі, зв'язки (hasMany, belongsTo), scopes, casts
├── Services/             # Бізнес-логіка та інтеграція із зовнішніми API (НБУ, Open-Meteo тощо)
└── Enums/                # Перелічувані типи (статуси замовлень, ролі користувачів тощо)
database/
├── factories/            # Фабрики для генерації тестових даних (Faker)
├── migrations/           # Міграції структури бази даних
└── seeders/              # Наповнення БД початковими та демонстраційними даними
docs/
└── diagrams/             # Сюди додайте ER-діаграму БД та UML-діаграми для захисту
```

## ✅ Чек-лист готовності до захисту (Definition of Done)

Перед здачею курсової роботи переконайтеся, що виконані всі базові технічні вимоги:

- [ ] **База даних:** Спроєктовано та реалізовано щонайменше 5 зв'язаних таблиць (використано зовнішні ключі `foreignId()->constrained()`).
- [ ] **Наповнення даними:** Написані `Factories` та `Seeders`. Команда `php artisan migrate:fresh --seed` відпрацьовує без помилок і створює повноцінні демо-дані.
- [ ] **Архітектура:** Бізнес-логіка та робота зі сторонніми сервісами винесені в окремі класи у `app/Services/`.
- [ ] **Зовнішнє API та кешування:** Реалізовано отримання даних із зовнішнього REST API з обробкою таймаутів/помилок (`Http::timeout()`) та кешуванням результатів (`Cache::remember()`).
- [ ] **Валідація та безпека:** Усі форми захищені `@csrf`, валідація винесена у `FormRequest`, налаштовано розмежування прав доступу (Auth / Policies / Gates).
- [ ] **Інтерфейс:** Використано шаблонізатор Blade (або Inertia/Livewire), інтерфейс коректно відображається на десктопі та мобільних пристроях.
- [ ] **Чистота коду:** Код відформатовано згідно зі стандартами PSR-12 за допомогою `./vendor/bin/pint`.
- [ ] **Документація:** Заповнено `README.md` вашого проєкту (тема, опис функціоналу, ER-діаграма бази даних, інструкція із запуску).

## 🛠️ Корисні команди для розробки

| Команда | Призначення |
| :--- | :--- |
| `./vendor/bin/pint` | Автоматичне форматування коду (PSR-12) |
| `php artisan test` | Запуск тестів |
| `php artisan migrate:fresh --seed` | Перестворення всіх таблиць БД та запуск сідерів |
| `php artisan route:list` | Перегляд усіх зареєстрованих маршрутів |
| `php artisan cache:clear` | Очищення кешу застосунку |

## ⚠️ Правила роботи з Git

> [!WARNING]
> **Категорично заборонено комітити в репозиторій:**
> * Файл `.env` з вашими паролями та API-ключами (оновлюйте лише `.env.example` без секретних значень).
> * Папки `vendor/` та `node_modules/`.
> * Файли локальної БД SQLite, якщо вони містять тимчасові дані (або додайте їх у `.gitignore`).

1. Кожен логічний етап розробки фіксуйте окремим осмисленим комітом (наприклад: `feat: add database migrations and models`, `feat: integrate NBU currency API with caching`).
2. Усі діаграми (ER-діаграма БД, Use Case) збережіть у форматі `.png` або `.svg` у папку `docs/diagrams/` та вставте їх у головний `README.md` вашого проєкту.
